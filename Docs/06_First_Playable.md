# 0.2 首轮可玩版本

历史版本：当前 0.3 已加入两职业、商店和 Boss，默认地图与操作入口见 `07_Progression_Prototype.md`。本文件保留首轮闭环的开发记录。

这是 UE4.27.2 的第一轮灰盒游戏闭环：营地进入副本 → 击杀与拾取 → 死亡或撤离 → 结算 → 返回营地再挑战。

## 启动

打开 AshenRift.uproject，默认关卡为 `/Game/AshenRift/Maps/L_FirstPlayable`，点击 Play。也可在 PowerShell 执行 `Tools/PlayPrototype.ps1`，直接用本机 UE4 打开独立试玩窗口。此方式仍依赖已安装的引擎，不是已经打包的发行版。

当前已生成编辑器模块和 Development 游戏目标。源码修改后先关闭试玩，再运行 `Tools/BuildProject.ps1`，随后打开工程或试玩。

## 操作

| 操作 | 按键 |
|---|---|
| 移动与视角 | WASD、鼠标 |
| 跳跃 | 空格 |
| 面向摄像机前方近战攻击 | 鼠标左键，间隔 0.6 秒 |
| 营地附近进入副本 | E |
| 蓝色传送阵内开始撤离 | E，等待 3 秒 |
| 药水回复 30 HP | Q，满血不消耗 |
| 简易本局背包 | Tab |
| 结算后返回营地，保存失败时重试 | R |

第一轮从营地按 E 会传送到副本入口并生成三个敌人。入口前方有两瓶绿色药水，靠近会自动拾取。击杀敌人掉落金币，每只 10，靠近自动拾取。沿中央通道前进，撤离传送阵在第三个区域的侧边；站入圆形范围按 E，留在范围内等待 3 秒。受伤或离开范围会取消，需要重新按 E。

死亡时本局金币和物品全部损失。撤离时金币与背包物品写入永久档案，然后清空临时背包。结算页面按 R 恢复满血并返回营地，下一局重新生成敌人与初始药水。保存失败时保持待保存状态，按 R 重试，不会重复累加银行。

## 实现入口

- `Source/AshenRift/ARPrototype.h/.cpp`：玩家、敌人、拾取、传送阵、GameMode 和临时 HUD。
- `BP_ARPlayableCharacter`：原生 ARPlayerCharacter 的蓝图子类，已包含 Health、Inventory、相机和临时武器，不要重复添加组件。
- `BP_ARGrunt`：原生 AREnemy 的蓝图子类，可配置 HP、伤害、速度、追击距离与奖励。
- `BP_ARPlayableGameMode`：原生 ARPrototypeGameMode 的蓝图子类，引用玩家和敌人子类。
- `ARRunGameInstance`：本局状态、银行、永久档案与结算事务。继续沿用 0.1 的数据约定。
- `Scripts/create_first_playable.py`：一次性初始化，已有地图时拒绝覆盖。开发时直接在编辑器改关卡，不要反复重建。

原始灰盒的独立备份为 `/Game/AshenRift/Maps/L_OriginalGreybox_Backup_20261028`。初始化中发现 UE4 save_map 另存并不切换当前世界，初次改动曾落在 L_Prototype；已修正初始化脚本并从未修改的另存副本保存原始备份。后续使用 L_FirstPlayable 开发，原型历史文件无需作为当前启动地图。

## 本版边界

此版本使用白盒/灰盒场景、模板人形、简单武器摆动和英文 HUD。没有正式攻击动画、受击动画、死亡动画、美术氛围、音效或最终 UI。

敌人使用直线追击与可见性检测，会被掩体阻挡；没有绕障导航或复杂 AI。撤离传送阵位于固定房间；房间顺序不随机。Boss 区只预留空间，没有 Boss。

尚未制作第二职业、商店交易、装备槽、技能、天赋购买和随机房间。永久档案已预留仓库、符文与天赋字段，但预留字段不代表相关玩法完成。当前不开放从仓库带入装备。

下一阶段先改进战斗反馈和敌人导航，再接入可交互商店与职业差异；随机房间和 Boss 在这些接口稳定后扩展。
